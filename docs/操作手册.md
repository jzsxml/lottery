# 年会抽奖系统 · 操作手册

适用版本：阶段一至四 · **单机部署 · 200 人以内**

---

## 1. 系统组成

| 入口 | 地址（开发） | 地址（生产 `npm run build` 后） | 用途 |
|------|----------------|----------------------------------|------|
| 管理台 | http://127.0.0.1:5173 | http://本机IP:3000 | 导入名单、设置、备份、审计 |
| 大屏 | http://127.0.0.1:5173/screen | http://本机IP:3000/screen | 现场投影，全屏 F11 |
| 移动主持 | http://127.0.0.1:5173/host | http://本机IP:3000/host | 手机/Pad 开始/停止 |
| API | http://127.0.0.1:3000/api | 同上 | 健康检查 `/api/health` |

数据文件：`data/lottery.db`（SQLite）。**会前请备份整库到 U 盘。**

## 2. 安装与启动

### 2.1 首次安装

```bash
cd d:\test\lottery
npm install
```

### 2.2 开发模式（彩排推荐）

```bash
npm run dev
```

- 后端默认 **3000**，前端 **5173**（API 通过 Vite 代理）
- **勿**在系统中长期设置 `PORT=3002` 等变量，否则代理会对不上

### 2.3 现场生产模式（单进程托管页面）

```bash
npm run build
npm run start -w server
```

浏览器访问 `http://本机局域网IP:3000`；大屏与主持使用同一 IP，不同路径。

### 2.4 重启服务

1. 关闭旧终端中的 `npm run dev`（或任务管理器结束 `node`）
2. 确认 3000/5173 未被占用后重新 `npm run dev`
3. 若 PowerShell 曾设置过 `$env:PORT`，执行：`Remove-Item Env:PORT -ErrorAction SilentlyContinue`

## 3. 角色与权限

在管理台页头 **当前角色** 下拉切换（请求头 `X-Lottery-Role`）。打开过 **移动主持** `/host` 不会改写管理台角色；若曾用旧版本导致一直是「主持」，在此改回 **管理员** 即可。

| 角色 | 典型使用者 | 主要能力 |
|------|------------|----------|
| **admin** | IT / 主管 | 全部：设置、导入、作废、解锁活动 |
| **operator** | HR | 导入、活动设置、签到、作废、大屏控制 |
| **host** | 主持人 | 大屏开始/停止/复位、签到勾选；**不能**改设置/导入/作废 |

**主持 PIN**（活动设置 → 外观与音效）：

- 保存 PIN 后，**移动主持 `/host`** 须先输入 PIN
- 管理台 `operator` / `admin` 控制台操作大屏**免 PIN**
- PIN 经 `X-Host-Pin` 传给后端校验

## 5. 名单导入

### 5.1 表头格式

任选：

- `工号, 姓名, 部门`
- `emp_no, name, department`

### 5.2 规则

- **工号**本活动内唯一；重复导入会**更新**姓名与部门
- 已有抽奖记录时，**不允许清空名单**
- 导入需 **admin / operator** 角色

### 5.3 模板下载

| 方式 | 路径 |
|------|------|
| 管理台名单页 | **下载 CSV 模板** / **下载 Excel 模板** |
| API | `GET /api/templates/participants.csv`、`GET /api/templates/participants.xlsx` |
| 项目目录 | `data/templates/participants-import-template.csv` / `.xlsx` |

说明见 `data/templates/README.md`。

### 5.4 示例文件

`data/sample-participants.csv`（与模板格式相同）

## 6. 参与资格（活动设置 Tab）

| 模式 | 含义 |
|------|------|
| **全员** | 不签到，在岗名单均可进池（仍受「已中奖」排除） |
| **仅已签到** | 名单 Tab 勾选签到者进池 |
| **手动可参与** | 勾选「可参与」者进池 |
| **混合** | 须**同时**签到且可参与 |

名单 Tab 顶部显示：**可参与 / 在册** 人数。

**每轮开始滚动**时冻结抽奖池快照；进行中改签到**不影响已开滚动轮次**。

## 7. 奖项配置

- **排序**：按 `sort_order` 展示，建议先小后大
- **每轮人数 k**：须 ≤ 当前可参与人数
- 已抽奖奖项状态为 `completed`，不可再删改人数
- 作废整轮后可恢复为 `pending`（见 §10）

---

## 8. 现场抽奖流程（标准）

### 8.1 设备分工

| 设备 | 页面 | 操作人员 |
|------|------|----------|
| 投影仪 | `/screen` | 只看，不点 |
| 操作电脑 | 管理台「抽奖」或 `/host` | 主持 / 操作员 |

### 8.2 状态机

`idle` → **开始滚动** → `rolling` → **停止并抽奖** → `slowing`（约 3.5s）→ `result` → **复位 idle** → 下一奖

| 步骤 | 操作 | 系统行为 |
|------|------|----------|
| 1 | 选择奖项 → **开始滚动** | 冻结池、大屏 3D 球加速、WebSocket 同步 |
| 2 | **停止并抽奖** | 服务端 Fisher–Yates 落库，结果锁定 |
| 3 | （自动） | 大屏减速、揭晓、撒花 |
| 4 | **复位 idle** | 准备下一奖项 |

### 8.3 彩排 / 应急

- **快速抽奖（无动画）**：管理台抽奖 Tab，跳过滚动仍写审计
- 大屏断网刷新：IndexedDB 缓存 + `/api/screen/state` + WebSocket 重连

## 9. 外观与音效（活动设置）

- **风格预设**：活动设置 → 外观 → 星际蓝金 / 喜庆红金 / 赛博青紫 / 黑金晚宴 / 清新绿意 / 自定义；点卡片预览，**保存外观** 后大屏刷新生效
- **姓名滚动方式**：球面旋转 / 随机滑动 / 姓名瀑布 / 喷泉上扬 / 火山喷发
- **背景特效**：经典光晕 / 星空 / 海水 / 火焰 / 极光（与滚动方式、配色独立）；保存后大屏约 12 秒自动拉取，或手动刷新 `/screen`
- 亦可微调主色 / 强调色 / 背景（将自动记为「自定义」）
- Logo：填**可公网或局域网访问的图片 URL**（非本地上传）
- 音效：须大屏上点击 **「开启音效」** 后才有滚动/揭晓音
- **主持 PIN**：留空表示不校验

## 10. 异常与重抽

### 10.1 未到场 / 结果无效

1. 管理台 → **结果与导出**
2. 对状态为 `locked` 的轮次 → **作废/重抽**
3. 必填原因，二次确认
4. 该轮标记 `voided`，中奖记入作废；**奖项恢复待抽**
5. 重新走 §8 流程

> 系统**不修改**原中奖记录行，仅 `is_voided` + 新轮次，审计可追溯。

### 10.2 可参与人数不足

提示「可抽奖人数不足」时：检查资格模式、签到人数、是否人人已中奖。

### 10.3 大屏卡在 rolling

- 操作端点 **停止并抽奖**；若失败看管理台报错
- 仍异常：**复位 idle**，确认奖项状态后重新开始（勿重复点「开始」）

### 10.4 HTTP 415 / 接口失败

- 确保后端为**最新代码**（已支持空 JSON POST）
- 开发模式确认后端在 **3000**，非 3002
- 重启 `npm run dev`

## 12. 运维与压测（勿在正赛库随意执行）

| 命令 | 作用 |
|------|------|
| `npm run audit:verify -w server -- 1` | 校验轮次 1 哈希与结果一致性 |
| `npm run stress:test -w server` | 补足 200 人并连抽 15 轮测性能 |
| `npm run reset:test -w server` | **清空测试数据**：名单、抽奖记录、大屏复位；奖项定义保留 |
| `RESET_PRIZES=1 npm run reset:test -w server` | 同时删除所有奖项 |
| `RESET_AUDIT=1 npm run reset:test -w server` | 同时清空操作日志 |

**警告**：`stress:test` / `reset:test` 会**清空本场抽奖记录**，请在备份库或彩排环境运行。

## 13. 局域网手机主持

1. 查看电脑上 `ipconfig`，例如 `192.168.0.104`
2. 手机浏览器：`http://192.168.0.104:5173/host`（开发）或 `:3000/host`（生产）
3. 输入主持 PIN（若启用）
4. 与电脑操作二选一即可，勿双人同时狂点

生产环境若需外网，需自行做内网穿透；默认设计为**不上传云端、仅局域网**。

### 安全提示（单机部署）

- 权限依赖请求头 `X-Lottery-Role`（管理台/主持页自动附带），**未带头请求的写操作会被拒绝**；请勿把服务暴露到公网。
- 主持 PIN 仅存服务端，接口不返回明文；校验使用时间安全比较。
- Logo 仅允许 `http://` / `https://` URL，主题色为合法十六进制，防止恶意外链。
- 奖项增删改、快速抽奖、导出结果、审计日志等接口已强制角色校验。

## 14. 公平性说明（对外口径）

- 随机：Node `crypto` + Fisher–Yates，非 `Math.random` 取模
- 每轮留存：池快照哈希、随机种子、结果哈希、链式 `audit_logs`
- 滚动动画**不决定**中奖；结果以停止时服务端抽成为准
- 资格规则以轮次开始时快照为准（`pool_policy` 可查）

## 15. 常见问题速查

| 现象 | 处理 |
|------|------|
| 管理台 API 全失败 | 后端未启或端口不对；看 `http://127.0.0.1:3000/api/health` |
| 大屏不更新 | 检查 WebSocket；刷新大屏；看角标「实时连接」 |
| 主持无法开始 | 角色是否为 host/admin/operator；PIN 是否正确 |
| 导入乱码 | CSV 保存为 UTF-8 |
| 主题不生效 | 保存外观后刷新大屏 |
| Git/多旧 node 占端口 | 结束旧进程后重启 dev |
